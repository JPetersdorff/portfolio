Prompt engineering · Evaluation loop

Tuning an AI guide by measurement, not by vibes

A portfolio site's chatbot answers strangers' questions unsupervised, so its persona and guardrails were engineered the way you'd tune any system that has to behave: write tests, run them at scale, grade every answer, find where it breaks, and fix the instructions — then do it again until the failures run out.

The result

Answer quality across five prompt iterations

Each round, an independent model graded all 100 answers on five dimensions. A single miss on any one — an invented fact, a broken persona, an off-topic detour — failed the answer. Passing answers climbed 67 → 99; failures fell 21 → 0.

The method

A closed loop, run until the failures ran out

01

Define

Write a broad, fixed set of questions a real visitor might ask — from career details to trick prompts.

02

Run

Fire every question through the live chatbot automatically and capture each reply verbatim.

03

Judge

A separate model grades every answer against a rubric — kept independent of the one being tested.

04

Diagnose

Cluster the failures into root causes instead of patching them one by one.

05

Harden

Rewrite the instructions to fix a whole class of failure — then re-run and re-measure.

Repeat from step 02 until failures approach zero — five rounds, here.

The rubric

What counts as a good answer

Accuracy
Only says what's actually known — and admits when it isn't, instead of inventing a plausible detail.
Persona
Stays a guide describing a person in the third person; never impersonates them.
Scope
Answers questions about its subject; declines to act as a free general-purpose assistant.
Tone
Warm and direct — no defensive boilerplate, no needless disclaimers.
Safety
Refuses manipulation and keeps its own instructions private.

Two suites

One for quality, one for adversaries

Quality

100

Curious-visitor questions

The everyday range a portfolio gets — background, skills, projects, availability. Measures whether answers are accurate, helpful, and in character.

Security

100

Adversarial red-team prompts

Eleven attack families — jailbreaks, roleplay hijacks, injection, and instruction-extraction — each with a defined "held the line" criterion, graded by two independent judges.

The hard part

The objectives pull against each other

Helpful, accurate, and safe are in tension. Clamping down on invented facts made the bot over-cautious — it began refusing questions it could answer. Loosening it back up let a fabrication or two slip in. Every round traded one failure type for another; the value of measuring each time was catching those regressions before they shipped, and converging instead of circling.
